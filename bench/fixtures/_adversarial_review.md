## BLOCKER â affects the whole battery

**B0. The grading ground truth does not exist in the fixture.**
The battery cites `qa_pairs` (22), `expected_fact`, and a `mined corrections` list as the gold standard for RL-1, RL-3, RL-4, RL-5, RL-7, RL-9. Every test that scores against "the matching `qa_pairs` expected_fact" currently has **no gold to grade against** â they would either crash or, worse, be silently hand-graded by whoever runs them, which is itself a confound (grader sees the needle they planted). **Fix:** before any test runs, author and commit a `qa_pairs`/`corrections` block to the fixture (query, gold `source`, gold `expected_fact` substring, and for corrections the old/new value pair), and have each test assert the gold ref exists in the seeded store. ## (1) Grading leakage â query shares rare tokens with the answer, BM25 wins trivially

**RL-1 "exact" arm â leakage is the entire arm, and that is fine, but the headline metric is contaminated.** The exact phrasing ("set_updated_at fixed search_path security advisor") shares the rare token `set_updated_at` with exactly one paragraph (2 occurrences in corpus) and `search_path` appears **0 times** in `doc_paragraphs` â so the exact query's rare token is *absent from the corpus entirely*. The exact arm will rank on `set_updated_at` alone, which is genuine leakage by construction. That is acceptable as the *positive control*, but the headline `recall@1(exact) â recall@1(paraphrase)` is then measuring "does a unique token win" (trivially yes) minus "does a zero-overlap paraphrase win" (trivially no) â a delta that is mechanically guaranteed and proves nothing about real usage. **Fix:** drop the contrived exact phrasing; build the exact arm from the paragraph's *natural* mid-frequency wording and report the delta against paraphrase only for QA pairs where the gold token's corpus df â¥ 3 (so a rare-token shortcut can't dominate). Also fix the stated needle: `search_path` is not in the corpus.

**RL-4 â the gold token is near-unique, so "rank 1" is leakage not disambiguation.** `service_role` appears 7Ã but the full gold phrase "SUPABASE_SERVICE_ROLE_KEY ... runs outside an authenticated request" is concentrated; `sonar-deep-research` appears 7Ã and `gpt-4.1` 5Ã. The test claims to measure *same-key wrong-value* precision, but the query "which key does the Trigger.dev worker use to write rows" contains `triggerdev` (1 occurrence) and `service_role`-adjacent tokens â BM25 can win on the rare `triggerdev`/`worker` tokens without ever disambiguating among the key distractors. **Fix:** strip the rare disambiguating tokens from the query (ask the question in the user's natural words that collide with all four key paragraphs equally), and only then measure precision@5. ## (3) Tests that would "pass" for the wrong reason
